Transforms

Overview

The transform maps the coordinates you draw in, user space, onto the coordinates of the surface, device space. translate, rotate, scale and skew compose: each applies on top of the transform already in effect. transform instead reads or replaces the matrix outright.

Figure 1. Each operation applied to the same square, which is drawn once by the same call. The outline is where it lands with no transform.

Angles are in radians, and Artist’s y axis grows downward, so a positive angle turns clockwise on screen. Rotation, scaling and skewing are about the origin of user space, not the centre of what you are drawing: translate first to work about another point, as the Example does.

The transform is part of the canvas state, so save and restore, under States, put back the one that was in effect.

A canvas may already carry a transform when you get it: a host window can set one for its drawing area, and a canvas over an image carries that image’s scale. user_to_device and device_to_user are relative to it, so what you get back does not depend on what the host or the image set up.

Expressions

Notation

Object of type canvas.

Object of type point.

x, y

float coordinates.

xy

A float scale factor for both axes.

rad

A float, an angle in radians.

sx, sy

double angles in radians.

mat

Object of type affine_transform. a, b, c,

d, tx, ty

double members of a transform matrix.

Composition

Expression Semantics Return Type

cnv.translate(p)

Move the origin of user space by p.

void

cnv.translate(x, y)

As above, by x and y.

void

cnv.rotate(rad)

Rotate user space about its origin by rad.

void

cnv.scale(p)

Scale user space by p.x and p.y.

void

cnv.scale(xy)

Scale both axes by xy.

void

cnv.scale(x, y)

Scale by x and y.

void

cnv.skew(sx, sy)

Skew user space: sx is the angle by which y shears with x, and sy the angle by which x shears with y.

void

Each call composes on top of the transform in effect, so the call nearest the drawing is the one applied first to it: scaling by 2 and then translating by 10 moves by 20 device units. Everything drawn afterwards follows the transform, line widths and text included.

The angles skew takes are the ones affine_transform skew and make_skew take.

Conversion

Expression Semantics Return Type

cnv.user_to_device(p)

Where the user space point p lands in device space.

point

cnv.user_to_device(x, y)

As above, for the point x, y.

point

cnv.device_to_user(p)

The user space point that the device space point p came from. This is what a mouse position needs.

point

cnv.device_to_user(x, y)

As above, for the point x, y.

point

The two are inverses of each other, and both are relative to the transform the canvas already carried when it was made.

The Matrix

Expression Semantics Return Type

cnv.transform()

The current matrix.

affine_transform

cnv.transform(mat)

Replace the current matrix with mat.

void

cnv.transform(a, b, c, d, tx, ty)

Replace it with the six members of a matrix.

void
These three work on the backend’s own matrix, not on a matrix relative to what the canvas started with, and its value for the same drawing state is not the same on every backend. Replacing it therefore throws away whatever the host or the image set up, such as a window offset or an image’s scale. Prefer save and restore for putting a transform back, and give transform(mat) only a matrix that transform() returned from the same canvas.

Example

Rotating a rectangle about its own centre, and putting the transform back afterwards:

   auto state = cnv.new_state();

   cnv.translate(center.x, center.y);
   cnv.rotate(pi / 6);
   cnv.translate(-center.x, -center.y);

   cnv.add_rect(r);
   cnv.fill_style(colors::gold);
   cnv.fill();
