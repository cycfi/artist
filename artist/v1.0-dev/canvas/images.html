Drawing Images

Overview

draw paints an image onto the canvas. The Image page covers the image itself: loading one, building one from pixels, and drawing into one. The eight calls here differ only in how much of the image is painted, where it lands, and at what size.

The ink is the image’s own. Unlike every other paint on the canvas, the fill and stroke styles do not colour it, and the current path is neither painted with it nor disturbed by it. Everything else about the drawing state applies as it would to any other paint: the geometry goes through the current transform, the clip cuts it, the image is composited over what is already there, and the shadow and the compositing operator take effect.

Positions and rectangles passed to draw are in user space. The image’s own size(), and the src rectangle, are in the image’s units, whatever its scale. A 2x image covers the same ground as a 1x image of the same size(); it carries more detail into it.

These are the W3C canvas API’s drawImage, in its three argument counts, spelled as C++ overloads.

Include

#include <artist/canvas.hpp>

The two layer overloads need the layer’s own header as well:

#include <artist/canvas_layer.hpp>

Declaration

   void  draw(image const& pic, rect const& src, rect const& dest);
   void  draw(image const& pic, rect const& dest);
   void  draw(image const& pic, point pos = {0, 0});
   void  draw(image const& pic, point pos, float scale);
   void  draw(image const& pic, float posx, float posy);
   void  draw(image const& pic, float posx, float posy, float scale);

   void  draw(canvas_layer const& layer, rect const& dest);
   void  draw(canvas_layer const& layer, point pos = {0, 0});

A float multiplier on the image’s own size.

Placing an Image

Expression Semantics Return Type

cnv.draw(pic)

Paint the whole image with its top left corner at the origin.

void

cnv.draw(pic, pos)

As above, with the corner at pos.

void

cnv.draw(pic, posx, posy)

As above, from loose coordinates.

void

The image is painted at pic.size(), its own units, not at its pixel count. An image loaded at 2x has twice the pixels of a 1x one of the same size() and covers exactly the same ground; the extra pixels go into the detail. That is what makes one drawing work on displays of different densities.

Scaling an Image

Expression Semantics Return Type

cnv.draw(pic, pos, scale)

Paint the whole image at pos, its size multiplied by scale.

void

cnv.draw(pic, posx, posy, scale)

As above, from loose coordinates.

void

cnv.draw(pic, dest)

Paint the whole image stretched to fill dest.

void
Figure 1. The same image placed three ways.

scale multiplies both axes, so the shape is kept. dest does not: the two axes stretch independently to reach its edges, and an image put into a rectangle of another proportion comes out squashed, as the rightmost figure above shows. Compute dest from the image’s own aspect ratio where that matters.

Nothing is painted outside dest, and an empty dest, one with zero width or zero height, paints nothing at all.

Enlarging is smoothed rather than blocky: a pixel of the image spread over several pixels of the canvas is interpolated, so a small image blown up comes out soft. There is no control over that.

Drawing Part of an Image

Expression Semantics Return Type

cnv.draw(pic, src, dest)

Paint the region src of the image, stretched to fill dest.

void
Figure 2. Lifting one frame out of a sheet.

This is how a single frame is taken from a sprite sheet, and it is the form the other five are built from: each of them calls this one with src covering the whole image.

src is in the image’s own units, the same units as size(), so it names the same region of a 2x image as of a 1x one. That is the point of the choice: a sheet can be swapped for a denser one without touching the arithmetic that picks the frames out of it. In the figure above the cells are 32 units wide, so the third of them starts 64 units in, which is the 64 in src.

Keep src inside the image and give both rectangles a positive width and height. Outside that the backends disagree, and none of the three cases is settled. A src that runs past the image’s edge is clipped to it and the result stretched over the whole of dest on Quartz 2D, while Cairo shrinks what it paints in proportion, as the W3C API says to. A src of zero width or height paints nothing on Cairo, again as the W3C API says, and the whole image stretched across dest on Quartz 2D. A dest whose right is left of its left mirrors the image on Cairo and does not on Quartz 2D.

Drawing a Layer

Expression Semantics Return Type

cnv.draw(layer)

Paint the whole layer with its top left corner at the origin.

void

cnv.draw(layer, pos)

As above, with the corner at pos.

void

cnv.draw(layer, dest)

Paint the whole layer stretched to fill dest.

void

A canvas_layer is an offscreen surface made for one canvas, living on that canvas’s device at that canvas’s pixel density. It is the buffer to reach for when the same drawing is put down every frame, an animation for instance: draw into it once through its context(), then paint it with draw as often as needed. It keeps what was drawn into it between frames, and unlike an offscreen_image it offers no access to its pixels.

Its size() is in user space units, like an image’s, so drawing it at pos covers layer.size() units from there however dense the canvas underneath is. A layer is valid only for the canvas it was made for.

Example

A seven segment display. The ten digits are rendered once into a single sheet, and a reading is then put together by painting one frame of that sheet per digit, which is what a sprite sheet is for:

   // One seven segment digit in a 32 by 32 cell, at the corner `at`.
   void draw_digit(canvas& cnv, int n, point at)
   {
      // Three segment shapes in a 16 by 26 digit: the horizontal bar across
      // the top, the vertical post down one side, and the pointed middle
      // bar. The bar is 16 long and the post 13, so they are not one shape
      // turned; the other four segments are these two turned half a turn.
      static path const bar{"M 0.5 0 L 15.5 0 L 13.1 2.4 L 2.9 2.4 Z"};
      static path const post{"M 0 0.5 L 0 12.5 L 2.4 10.1 L 2.4 2.9 Z"};
      static path const mid{
         "M 0 13 L 1.2 11.8 L 14.8 11.8 L 16 13 L 14.8 14.2 L 1.2 14.2 Z"
      };

      // Segments a to g: the shape, where it goes, and whether it is turned.
      struct placement { path const& shape; float x, y; bool turned; };
      static placement const seg[] =
      {
         {bar, 0, 0, false},   {post, 16, 13, true},  {post, 16, 26, true},
         {bar, 16, 26, true},  {post, 0, 13, false},  {post, 0, 0, false},
         {mid, 0, 0, false}
      };
      static int const lit[] =
         {0x3f, 0x06, 0x5b, 0x4f, 0x66, 0x6d, 0x7d, 0x07, 0x7f, 0x6f};

      auto st = cnv.new_state();
      cnv.fill_style(rgba(26, 26, 26, 255));
      cnv.fill_round_rect(rect{at.x, at.y, at.x + 32, at.y + 32}, 4);
      cnv.translate(at.x + 8, at.y + 3);

      for (int i = 0; i != 7; ++i)
      {
         auto seg_state = cnv.new_state();
         cnv.translate(seg[i].x, seg[i].y);
         if (seg[i].turned)
            cnv.rotate(cycfi::pi);
         cnv.fill_style(
            ((lit[n] >> i) & 1)?
               rgba(255, 255, 255, 255) : rgba(255, 255, 255, 12)
         );
         cnv.add_path(seg[i].shape);
         cnv.fill();
      }
   }

   // The ten digits, rendered once into one 320 by 32 sheet.
   auto sheet = image{320, 32};
   {
      offscreen_image ctx{sheet};
      canvas scnv{ctx.context()};
      for (int d = 0; d != 10; ++d)
         draw_digit(scnv, d, point{d * 32.0f, 0});
   }

   // A reading, blitted from the sheet one digit at a time. The 2 is drawn
   // twice, from the one cell that holds it.
   cnv.draw(sheet, point{20, 20});
   char const* reading = "2026";
   for (int i = 0; reading[i]; ++i)
   {
      float x = (reading[i] - '0') * 32.0f;
      cnv.draw(
         sheet,
         rect{x, 0, x + 32, 32},
         rect{60 + i * 64.0f, 70, 108 + i * 64.0f, 118}
      );
   }
Figure 3. What the code above draws.

The segment drawing runs ten times, once, whatever the reading is and however often it changes after that. Every later frame is four draw calls against a sheet that is already rasterised, and the digit 2 is painted twice from the one cell that holds it. Each cell is enlarged from 32 units to 48 on the way out, which is why the reading is softer than the sheet above it; a sheet is usually authored at the largest size it will be drawn.
