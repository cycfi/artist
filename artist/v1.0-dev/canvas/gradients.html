Gradients

Overview

A gradient is a paint that changes across the shape it fills, and it goes anywhere a color goes: as the fill style or the stroke style, under fill, stroke, fill_rect, fill_text and the rest. You build one in two steps. First give it its geometry, a line for a linear_gradient or a pair of circles for a radial_gradient. Then add color stops along it, each a color at a position between the two ends.

The geometry is in user space, read under the transform in effect when the path is painted, not when the style is set. A gradient therefore moves, scales and rotates with everything else drawn under that transform.

Artist follows the W3C canvas API, where these are createLinearGradient, createRadialGradient and addColorStop on a CanvasGradient. Artist makes the gradient a plain value you construct yourself rather than one the canvas hands back.

Include

#include <artist/canvas.hpp>

Declaration

   struct color_stop
   {
      float          offset;
      struct color   color;
   };

   struct gradient
   {
      void  add_color_stop(color_stop cs);
      void  add_color_stop(float offset, struct color color_);

      std::vector<color_stop> color_space = {};
   };

   struct linear_gradient : gradient
   {
      linear_gradient(float startx, float starty, float endx, float endy);
      linear_gradient(point start, point end);

      point start = {};
      point end = {};
   };

   struct radial_gradient : gradient
   {
      radial_gradient(
         float c1x, float c1y, float c1r,
         float c2x, float c2y, float c2r
      );

      radial_gradient(
         point c1, float c1r,
         point c2, float c2r
      );

      point c1 = {};
      float c1_radius = {};
      point c2 = c1;
      float c2_radius = c1_radius;
   };

The four style setters that take them:

   void  fill_style(linear_gradient const& gr);
   void  fill_style(radial_gradient const& gr);
   void  stroke_style(linear_gradient const& gr);
   void  stroke_style(radial_gradient const& gr);

All of these are nested in canvas, so the types are spelled canvas::linear_gradient, canvas::radial_gradient and canvas::color_stop. Neither gradient has a default constructor: the geometry is given at construction and the stops are added afterwards.

Color Stops

Expression Semantics Return Type

gr.add_color_stop(offset, c)

Add a stop: the paint is c at offset along the gradient.

void

gr.add_color_stop(cs)

The same, with the position and the color given as one color_stop.

void
Figure 1. What the stop list does to the ramp.

Between two stops the paint runs evenly from one color to the other, alpha included. Outside the outermost stops it does not repeat or fade: the first stop’s color is held all the way back to the start of whatever is being painted, and the last stop’s color all the way forward.

A gradient with one stop is that color everywhere, wherever the stop sits. A gradient with no stops at all paints nothing, as the W3C API specifies.

Stops need not be added in order of offset; they are sorted by offset before painting. Two stops at the same offset make a hard edge, with no blend between them, which is the way to build a band of flat colors in one paint.

Artist checks none of this. An offset outside 0 to 1 is not defined by the W3C API, and the backends disagree on what it does, so keep offsets inside that range. The same holds for a negative radius.

Linear Gradient Construction

Expression Semantics

canvas::linear_gradient{start, end}

A gradient running along the line from start to end.

canvas::linear_gradient{startx, starty, endx, endy}

The same, with the two points given as four scalars.
Figure 2. A two stop linear gradient. The ramp runs between start and end; each end color is held past it.

Offset 0 sits at start and offset 1 at end. The paint is constant along every line perpendicular to that one, so the line sets both the direction of the ramp and how long it takes: a short line packs the whole ramp into a narrow band, and a line at an angle tilts it.

Give the two points distinct values. The W3C API paints nothing when start and end are the same point, and Artist’s backends do not agree on that case.

Radial Gradient Construction

Expression Semantics

canvas::radial_gradient{c1, c1r, c2, c2r}

A gradient running from the circle at c1 of radius c1r to the circle at c2 of radius c2r.

canvas::radial_gradient{c1x, c1y, c1r, c2x, c2y, c2r}

The same, with the two centres given as scalars.
Figure 3. Where the two circles sit decides the shape of the gradient.

Offset 0 sits on the first circle and offset 1 on the second, and the ramp runs through the ring between them. The three useful arrangements are in the figure above:

  • The two circles concentric with c1_radius zero, which is the plain radial fill: the first stop’s color at the centre, spreading out to the second stop’s color at the rim.

  • The two circles concentric with c1_radius above zero, which holds the first stop’s color flat over a disc that wide before the ramp starts.

  • The first circle offset inside the second, which throws the highlight off centre and gives the cone-like look of a lit sphere.

Past the second circle the last stop’s color is held, as for a linear gradient. Two identical circles paint nothing, as the W3C API specifies.

On Direct2D the first circle’s radius is ignored. The backend’s radial brush has one radius and a focal offset, so c1_radius has nowhere to go; a Windows build renders the middle case above as the first.

Painting with a Gradient

Expression Semantics Return Type

cnv.fill_style(gr)

Fill with gr, replacing whatever paint the fill style held.

void

cnv.stroke_style(gr)

Stroke with gr, replacing whatever paint the stroke style held.

void

Fill and stroke are separate styles, so one path can be filled in one gradient and outlined in another. Setting a color replaces a gradient and setting a gradient replaces a color; there is one paint in each style at a time. Both are part of the state that save and restore keep.

The gradient is copied when the style is set. Adding a stop to the object afterwards changes the object, not the style, so build the gradient first and set it last.

Coordinates are read at paint time under the transform then in effect, not at the time of the fill_style call. A scale between the two stretches the ramp along with the shape, and one gradient painted twice under two different transforms lands in two different places.

On Quartz 2D a gradient’s stop colors do not match a flat fill of the same color. Stops go through kCGColorSpaceGenericRGB while a flat fill goes through the device space, so rgba(255, 0, 0, 255) as a stop renders as 255, 38, 0 and a mid grey comes out about 14 percent light. Black and white are unaffected. The Skia backend carries a matching correction factor for the same reason. Cairo renders stops exactly.

Example

A bar with a glassy sheen down it, and a round knob lit from the top left:

   auto box = rect{40, 40, 240, 92};
   canvas::linear_gradient sheen{box.left, box.top, box.left, box.bottom};
   sheen.add_color_stop(0, rgba(88, 152, 232, 255));
   sheen.add_color_stop(0.5, rgba(21, 101, 192, 255));
   sheen.add_color_stop(0.5, rgba(17, 82, 156, 255));
   sheen.add_color_stop(1, rgba(38, 118, 209, 255));
   cnv.fill_style(sheen);
   cnv.fill_round_rect(box, 8);

   auto knob = circle{300, 66, 26};
   canvas::radial_gradient lit{
      point{knob.cx - 10, knob.cy - 10}, 2,
      point{knob.cx, knob.cy}, knob.radius
   };
   lit.add_color_stop(0, rgba(150, 196, 255, 255));
   lit.add_color_stop(1, rgba(17, 82, 156, 255));
   cnv.fill_style(lit);
   cnv.add_circle(knob);
   cnv.fill();
Figure 4. What the code above draws.

The pair of stops at 0.5 is the hard edge that gives the bar its break across the middle. The knob’s highlight is off centre because the first circle is, which is the third arrangement in the radial figure above.
