Current Path

Overview

A canvas holds one path at a time, its current path. The calls on this page build geometry into it; fill and stroke paint it and then start a fresh one. The current path is not a path object you can hold: it lives in the canvas, is emptied by every paint, and is what clip, point_in_path and fill_extent all refer to.

This is the same geometry the path class describes, expressed as a sequence of calls rather than as an object. Build it here when the shape changes on every draw; build a path when the shape is fixed and worth keeping, then hand it over with add_path.

Everything is in user space, so the transforms under Transforms apply to the geometry as it is added. Coordinates come in two forms throughout: a point (or rect, or circle), and the same values as loose float arguments.

Artist follows the W3C canvas API, with one deliberate difference here. In the W3C API fill() and stroke() leave the path in place, and only beginPath() clears it. In Artist they consume it, and fill_preserve and stroke_preserve are the calls that do not.

Building

cnv.begin_path()

Discard the current path and start an empty one.

void

cnv.close_path()

Close the sub-path being built, by adding a straight line back to where it began.

void

cnv.move_to(p)

Start a new sub-path at p, which becomes the current point. Nothing is drawn.

void

cnv.move_to(x, y)

As above, at x, y.

void

cnv.line_to(p)

Add a straight line from the current point to p, which becomes the current point.

void

cnv.line_to(x, y)

As above, to x, y.

void

A path is a list of sub-paths, each a connected run of segments. move_to begins one, close_path closes one, and everything else extends the one being built. A path may hold several closed shapes, and how they combine when filled is the Fill Rule.

Both leave the current point in the direction of the first control point and arrive at end, which becomes the new current point.

Arcs

Expression Semantics Return Type

cnv.arc(p, radius, start_angle, end_angle, ccw)

void

cnv.arc(p, radius, start_angle, end_angle)

As above, with ccw at its default of false.

void

cnv.arc(x, y, radius, start_angle, end_angle, ccw)

As above, with a loose centre.

void

As above, with ccw at its default of false.

void

cnv.arc_to(p1, p2, radius)

Add an arc of the given radius tangent to the line from the current point to p1 and to the line from p1 to p2.

void

cnv.arc_to(x1, y1, x2, y2, radius)

As above, with loose coordinates.

void

Angles are in radians and are measured from the positive x axis. Artist’s y axis grows downward, so an increasing angle turns clockwise on screen, and ccw at its default of false sweeps in that direction.

Figure 1. The same start_angle and end_angle, swept each way. Angle 0 points along the positive x axis, and increasing angles turn clockwise because y grows downward.

arc joins the arc to the current point with a straight line if there is one, so call begin_path or move_to first when that is not wanted.

arc_to is the call that rounds a corner: p1 is the corner, and the arc replaces it. A straight line is added from the current point to where the arc begins, so the corner point itself is not on the path. With a radius of zero, or with the three points collinear, there is no corner to round and a straight line to p1 is added instead.

add_round_rect clamps radius to half the shorter side, so an over-large radius gives a stadium rather than a larger shape. A radius of zero gives a plain rectangle.

Building a path once and adding it with add_path on each draw is cheaper than rebuilding the geometry call by call, especially on a GPU backend.

round_rect and circle remain for code written against the Cairo-only canvas, but are deprecated and compile with a warning. Use add_round_rect and add_circle.

Painting

Expression Semantics Return Type

cnv.fill()

Fill the current path with the current fill style, then start a new path.

void

cnv.fill_preserve()

As above, but leave the path in place.

void

cnv.stroke()

Stroke the current path with the current stroke style, then start a new path.

void

cnv.stroke_preserve()

As above, but leave the path in place.

void

The styles these use, and the line width, cap and join that shape a stroke, are under Styles. The _preserve pair is how a shape is given both a fill and an outline:

   cnv.fill_preserve();    // fill, keeping the path
   cnv.stroke();           // then outline the same path, and clear it

Clipping

Expression Semantics Return Type

cnv.clip()

Restrict subsequent drawing to the current path, then start a new path.

void

cnv.clip(pth)

Restrict subsequent drawing to the path object pth.

void

cnv.clip_extent()

The smallest rectangle containing the clip region, in user space.

rect

Clipping intersects with whatever clip is already in effect, so it only ever narrows the drawable area. There is no call to widen it again: save the state first and restore it, as under States.

Queries

Expression Semantics Return Type

cnv.point_in_path(p)

Whether p lies inside the current path, by the current fill rule.

bool

cnv.point_in_path(x, y)

As above, for the point x, y.

bool

cnv.fill_extent()

The smallest rectangle that filling the current path would cover.

rect

fill_extent reports what a fill would cover, not what geometry is in the path, so a path with no enclosed area, a bare move_to and line_to for instance, reports rect(0, 0, 0, 0). So does an empty path.

fill_extent is declared by canvas.hpp but defined only by the Cairo backend. Calling it in a Quartz 2D or Skia build is a link error, not a compile error.

Fill Rule

Expression Semantics Return Type

cnv.fill_rule(rule)

Set the rule that decides what counts as inside a path that overlaps itself.

void
Figure 2. One self-intersecting five-pointed star, traced as a single path, filled under each rule.

path::fill_winding, the default, counts the direction of each crossing, so overlapping regions of one shape stay filled. path::fill_odd_even counts crossings alone, so every second region is left empty. The rule applies to fill, to clip and to point_in_path, and not to stroke.

Erasing

Expression Semantics Return Type

cnv.clear_rect(r)

Leave the region r transparent.

void

cnv.clear_rect(x, y, width, height)

As above, from a position and a size.

void

This erases rather than paints: the region is left transparent, not filled with a background color.

Backend Differences

The current path is the part of the canvas that leans hardest on the backend, and these are the places where the three do not agree. None of them is affected by a difference in the geometry itself; they are all about what a call does to the path around it.

Expression Quartz 2D Skia Cairo

cnv.add_circle(c)

An arc, joined to the current point by a straight line.

A closed sub-path of its own, with no joining line.

An arc, joined to the current point by a straight line.

cnv.add_path(pth)

Appends pth to the current path.

Replaces the current path with pth.

Appends pth to the current path.

cnv.clip(pth)

Clips to pth alone; the current path is left as it was.

Clips to pth alone; the current path is left as it was.

Appends pth to the current path, clips to the pair, then discards the path. It also leaves the context set to the fill rule of pth.

cnv.clear_rect(r)

Erases r; the current path is left as it was.

Erases r; the current path is left as it was.

Erases r and whatever is already in the current path, then discards the path.

cnv.fill_rule(rule)

True inside the fill only.

cnv.save() and cnv.restore()

Verified by running on Cairo and by reading lib/impl/skia/canvas.cpp, lib/impl/macos/quartz2d/canvas.mm and lib/include/artist/detail/canvas_impl.hpp.

On Quartz 2D, add_round_rect with a radius above zero begins a new path before adding the rounded rectangle, so it discards whatever was already being built. Cairo and Skia add to the path in place. Start a round rect on an empty path until this is settled.

Example

A rounded panel given both a fill and an outline, and the same shape rebuilt to hit test a mouse position:

   cnv.begin_path();
   cnv.add_round_rect(panel, 8);
   cnv.fill_style(colors::white.opacity(0.1));
   cnv.stroke_style(colors::white.opacity(0.4));
   cnv.line_width(1);
   cnv.fill_preserve();
   cnv.stroke();

   // The path is gone after stroke, so rebuild it to hit test.
   cnv.begin_path();
   cnv.add_round_rect(panel, 8);
   bool hot = cnv.point_in_path(mouse);
   cnv.begin_path();
