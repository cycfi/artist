Resources

Overview

Artist loads images by file name, and the name may be relative. A relative name is resolved against a process wide list of search directories: the first directory in the list that contains the file wins. The host application seeds the list, and applications add to it with add_search_path. find_file and find_directory search it.

Only the image constructors consult this list. Fonts are located through get_user_fonts_directory() and the platform’s own font machinery; see Font.

The list is guarded by a mutex, so add_search_path may be called from any thread, including while another thread is searching.

Include

#include <artist/resources.hpp>

Declaration

   void      add_search_path(
                fs::path const& path
              , bool search_first = false
             );
   fs::path  find_file(fs::path const& file);
   fs::path  find_directory(fs::path const& dir);
   // Declared by the library, defined by the host application
   extern void init_paths();

fs is the alias cycfi::fs, which <infra/filesystem.hpp> sets to std::filesystem, or to ghc::filesystem on a toolchain without it. The header includes it, and the alias is visible inside cycfi::artist.

Expressions

Notation

p

Object of type fs::path, a directory to search.

f

Object of type fs::path, a file name, relative or absolute.

d

Object of type fs::path, a directory name, relative or absolute.

Free Functions

Expression Semantics Return Type

add_search_path(p)

Append p to the list. It is searched after every directory already present.

void

add_search_path(p, true)

Insert p at the front of the list. It is searched first.

void

find_file(f)

If f is absolute, f itself when it exists. Otherwise the first p in the list for which p / f exists, returned as p / f. An empty path when nothing matches.

fs::path

find_directory(d)

As find_file, but a match must be a directory.

fs::path

add_search_path does not check that p exists and does not remove duplicates. Adding the same directory twice searches it twice.

find_file tests each candidate with fs::exists, which is true for a directory as well as a file, so a relative name that happens to match a directory is returned. find_directory is strict: it tests with fs::is_directory and never returns a file. There is no function that accepts only files.

An absolute path bypasses the list entirely. It is returned when it exists and an empty path when it does not, whatever the list holds.

Host Hook

Expression Semantics Return Type

init_paths()

Seed the search list. The library declares this and the host application defines it; every host under examples/host/ provides one, typically adding the application’s resource directory. The library calls it itself the first time find_file or find_directory runs. Do not call it.

void
A program that links Artist must define init_paths() or it does not link. The companion hook, get_user_fonts_directory(), is declared in font.hpp and is usually defined alongside it.
find_file and find_directory each carry their own one time initializer, so init_paths() runs once per function, up to twice in a process that calls both. A directory it adds then appears in the list twice. The header describes it as called only once; the discrepancy is recorded here as current behaviour and is not something to rely on.

Example

   // The host has already seeded the list from init_paths(). Add the
   // application's own asset directory, then an optional override that
   // must win over everything else.
   add_search_path("assets/textures");
   if (!user_override_dir.empty())
      add_search_path(user_override_dir, true);

   // image resolves a relative name through the same list.
   image tex{"wood.png"};

   // Or resolve it yourself and decide what to do on a miss.
   if (auto p = find_file("wood.png"); !p.empty())
      use(p);
