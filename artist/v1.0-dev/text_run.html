Text Run

Overview

A text_run is one paragraph of text in one font, shaped, broken into lines to fit a width, and then drawn and hit tested as a unit. It keeps its own copy of the text as UTF-32. text_layout, the multi-paragraph editor engine, is built from one text_run per paragraph.

Using one takes three steps: construct it, flow it to a width, and draw it. A run has no lines until it has been flowed, and replacing its text discards them, so flow again after every change of text.

Positions are relative to the run’s origin, the point on the first line’s baseline where a line with no offset would start: draw(cnv, p) puts the origin at p, and every caret_point y is a baseline. Indices are code point indices into text(), not UTF-8 byte offsets.

Figure 1. The output of the Example below, annotated. The caret is where mp falls, and the tint is the band caret_index maps to its line: it runs from the previous baseline down to this one.

A run draws with its own font and the colour it is given. The canvas font, fill style and text alignment play no part; the canvas transform does apply.

On Skia and Cairo, text is shaped with HarfBuzz and wrapped at the opportunities line_break reports. On Quartz 2D, Core Text both shapes and wraps it, so a wrap can fall somewhere line_break does not mark, and the same text can wrap differently from the other backends.

Layout

Expression Semantics Return Type

r.flow(w)

Break the text into lines no wider than w, each starting at x 0 and spaced by the font’s line_height().

void

r.flow(w, j)

As above, and justify if j is true.

void

r.flow(glf, fi)

Break the text into lines, asking glf where each line starts and how wide it may be.

void

r.num_lines()

The number of lines the last flow produced, 0 before the first. A text that ends in a hard break has an empty last line.

std::size_t

flow(glf, fi) calls glf(y) for each line, with y the baseline of that line measured from the first line’s baseline, and lays the line out at the returned li.offset in at most li.width. Varying the two with y flows text around a shape, or indents the first line. Lines are fi.line_height apart, except that the last line’s baseline is moved down by fi.last_line_height - fi.line_height.

A justified line has its spaces widened so that it fills its width exactly. The last line is left ragged, as is any line that ends in a hard break and any line whose natural width is 90% of its width or less.

Hit Testing

Expression Semantics Return Type

r.caret_point(i)

Where the caret before code point i goes: the left edge of its glyph, on its line’s baseline. An i at or past the end gives the end of the last line. {0, 0} before the first flow.

point

r.caret_index(p)

The index of the caret position nearest p, or text_run::npos if p is below the last line’s baseline. 0 before the first flow.

std::size_t

r.caret_index(x, y)

As above, for the point x, y.

std::size_t

caret_index picks the line first, and it is the first line whose baseline is at or below p.y. A p.y anywhere from just below the baseline of line k - 1 down to the baseline of line k therefore selects line k, and a point in the descenders of line k selects line k + 1. Within the line, an x at or before its start gives its first index, and an x at or past its end gives the index just past its last glyph: the space that ended it, or the next line’s first character. On the last line that is r.text().size(). Between the two, x rounds to the nearest glyph boundary.

On Quartz 2D, caret_point and caret_index count UTF-16 code units rather than code points. The two agree until the text holds a character outside the Basic Multilingual Plane, such as an emoji; past that point Quartz 2D’s indices no longer match text() or the break queries.
Where several code points share one glyph, as in the "fi" ligature, the caret positions inside it depend on the backend.

Break Queries

Expression Semantics Return Type

r.line_break(i)

Whether a line may break after code point i, by the Unicode line breaking rules (UAX #14).

text_run::break_enum

r.word_break(i)

Whether a word boundary follows code point i, by the Unicode word boundary rules (UAX #29).

text_run::break_enum
Value Meaning

text_run::must_break

A break is required after i, which is a hard line break such as '\n'.

text_run::allow_break

A break is allowed after i.

text_run::no_break

No break is allowed after i.

text_run::indeterminate

i is out of range, or, for line_break, the last code point of a text that does not end in a hard break.

word_break never reports must_break, and it reports allow_break for the last code point.

Constants

Expression Semantics Return Type

text_run::npos

Example

A justified paragraph with its first line indented, and a caret drawn where the mouse position mp falls in it:

   auto fd = font_descr{"Open Sans", 20};
   auto fm = font{fd}.metrics();
   auto lh = font{fd}.line_height();

   auto para = text_run{fd, text};
   para.flow(
      [](float y)
      {
         return y == 0
            ? text_run::line_info{30, 310}
            : text_run::line_info{0, 340};
      }
    , {true, lh, lh}
   );

   auto origin = point{60, 80};
   para.draw(cnv, origin);

   auto i = para.caret_index(mp.x - origin.x, mp.y - origin.y);
   if (i != text_run::npos)
   {
      auto cp = para.caret_point(i);
      cnv.stroke_style(colors::navy);
      cnv.move_to(origin.x + cp.x, origin.y + cp.y - fm.ascent);
      cnv.line_to(origin.x + cp.x, origin.y + cp.y + fm.descent);
      cnv.stroke();
   }
