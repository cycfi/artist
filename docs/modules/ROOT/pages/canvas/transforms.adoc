= Transforms

== Overview

The transform maps the coordinates you draw in, user space, onto the
coordinates of the surface, device space. `translate`, `rotate`, `scale`
and `skew` compose: each applies on top of the transform already in
effect. `transform` instead reads or replaces the matrix outright.

image::canvas/transforms.png[alt="The four composing transforms", width=560px, align=center, title="Each operation applied to the same square, which is drawn once by the same call. The outline is where it lands with no transform.", link={imagesdir}/canvas/transforms.png]

Angles are in radians, and Artist's y axis grows downward, so a positive
angle turns clockwise on screen. Rotation, scaling and skewing are about
the origin of user space, not the centre of what you are drawing: translate
first to work about another point, as the <<Example>> does.

The transform is part of the canvas state, so the end of a `new_state`
scope, under xref:canvas/states.adoc[States], puts back the one that was in
effect.

A canvas may already carry a transform when you get it: a host window can
set one for its drawing area, and a canvas over an
xref:foundation/image.adoc[image] carries that image's scale.
`user_to_device` and `device_to_user` are relative to it, so what you get
back does not depend on what the host or the image set up.

NOTE: See xref:canvas.adoc[Canvas] for the drawing model and an overview of the canvas.

== Include

```c++
#include <artist/canvas.hpp>
```

== Declaration

```c++
class canvas
{
public:

   void              translate(point p);
   void              rotate(float rad);
   void              scale(point p);
   void              skew(double sx, double sy);
   point             device_to_user(point p);
   point             user_to_device(point p);

   void              translate(float x, float y);
   void              scale(float xy);
   void              scale(float x, float y);
   point             device_to_user(float x, float y);
   point             user_to_device(float x, float y);

   affine_transform  transform() const;
   void              transform(affine_transform const& mat);
   void              transform(
                        double a
                      , double b
                      , double c
                      , double d
                      , double tx
                      , double ty
                     );
};

point                device_to_user(point p, canvas& cnv);
rect                 device_to_user(rect const& r, canvas& cnv);
```

== Expressions

The transform members of xref:canvas.adoc[`canvas`] allow these
expressions.

=== Notation

`cnv`                :: Object of type `canvas`.
`t`                  :: Object of type xref:foundation/point.adoc[point] for
                        a translation.
`tx`, `ty`           :: Floating point values for a translation.
`rad`                :: Floating point value for an angle in radians.
`k`                  :: Object of type `point` for the x and y scale
                        factors.
`sx`, `sy`           :: Floating point values for the x and y scale factors.
`s`                  :: Floating point value for a scale factor on both
                        axes.
`ax`, `ay`           :: Floating point values for the skew angles in
                        radians.
`p`                  :: Object of type `point` for a position.
`x`, `y`             :: Floating point values for a position.
`r`                  :: Object of type xref:foundation/rect.adoc[rect].
`mat`                :: Object of type
                        xref:foundation/affine_transform.adoc[affine_transform].
`a`, `b`, `c`, `d`   :: Floating point values for the linear part of a
                        matrix.

=== Mutators

[cols="1,1,1"]
|===
| Expression                          | Semantics                     | Return Type

| `cnv.transform(mat)`                | Set the current matrix to
                                        `mat`.                        | `void`
| `cnv.transform(a, b, c, d, tx, ty)` | Set the current matrix to the
                                        one with members `a`, `b`,
                                        `c`, `d`, `tx` and `ty`.      | `void`
|===

=== Accessors

[cols="1,1,1"]
|===
| Expression              | Semantics                     | Return Type

| `cnv.transform()`       | Get the current matrix.       | `affine_transform`
|===

WARNING: The three `transform` calls work on the backend's own matrix, not
on a matrix relative to what the canvas started with, and its value for the
same drawing state is not the same on every backend. Replacing it throws
away whatever the host or the image set up, such as a window offset or an
image's scale. Use a `new_state` scope to put a transform back, and give
`transform(mat)` only a matrix that `transform()` returned from the same
canvas.

=== Operation

[cols="1,1,1"]
|===
| Expression              | Semantics                          | Return Type

| `cnv.translate(t)`      | Move the origin of user space by
                            `t`.                               | `void`
| `cnv.translate(tx, ty)` | Move the origin of user space by
                            `tx` and `ty`.                     | `void`
| `cnv.rotate(rad)`       | Rotate user space about its origin
                            by `rad`.                          | `void`
| `cnv.scale(k)`          | Scale user space by `k.x` and
                            `k.y`.                             | `void`
| `cnv.scale(s)`          | Scale both axes of user space by
                            `s`.                               | `void`
| `cnv.scale(sx, sy)`     | Scale user space by `sx` and
                            `sy`.                              | `void`
| `cnv.skew(ax, ay)`      | Skew user space by `ax` (the angle
                            by which y shears with x) and `ay`
                            (the angle by which x shears with
                            y).                                | `void`
|===

Each call composes on top of the transform in effect, so the call nearest
the drawing is the one applied first to it: scaling by 2 and then
translating by 10 moves by 20 device units. Everything drawn afterwards
follows the transform, line widths and text included.

The angles `skew` takes are the ones
xref:foundation/affine_transform.adoc[affine_transform] `skew` and
`make_skew` take.

=== Conversions

[cols="1,1,1"]
|===
| Expression                    | Semantics                    | Return Type

| `cnv.user_to_device(p)`       | Convert `p` from user space
                                  to device space.             | `point`
| `cnv.user_to_device(x, y)`    | Convert the point `x`, `y`
                                  from user space to device
                                  space.                       | `point`
| `cnv.device_to_user(p)`       | Convert `p` from device space
                                  to user space.               | `point`
| `cnv.device_to_user(x, y)`    | Convert the point `x`, `y`
                                  from device space to user
                                  space.                       | `point`
| `device_to_user(p, cnv)`      | Convert `p` from device space
                                  to the user space of `cnv`.  | `point`
| `device_to_user(r, cnv)`      | Get the bounds of `r`'s
                                  corners, converted from
                                  device space to the user
                                  space of `cnv`.              | `rect`
|===

`user_to_device` and `device_to_user` are inverses of each other, and
both are relative to the transform the canvas already carried when it was
made. `device_to_user` is the one a mouse position needs. On Direct2D both
include the transform the render target carried instead; the hosts set
that to identity at the start of each frame, and an image's scale is
carried by its DPI, so the results are the same.

`device_to_user(p, cnv)` is `cnv.device_to_user(p)` as a free function.
`device_to_user(r, cnv)` converts all four corners of `r` and returns
their bounds, so the result holds the whole of `r` under a rotation or a
skew as well.

=== Example

Rotate a rectangle about its own centre, and put the transform back
afterwards.

```c++
#include <artist/canvas.hpp>
...
using namespace cycfi::artist;
extern canvas cnv;              // the canvas to draw on
...
   auto r = rect{40, 30, 200, 110};
   auto center = center_point(r);

   {
      auto state = cnv.new_state();

      cnv.translate(center.x, center.y);                    <1>
      cnv.rotate(cycfi::pi / 6);                            <2>
      cnv.translate(-center.x, -center.y);                  <3>

      cnv.add_rect(r);
      cnv.fill_style(colors::gold);
      cnv.fill();
   }

   // The state is back, so this outlines r where it started.
   cnv.add_rect(r);                                         <4>
   cnv.stroke_style(colors::gray[60]);
   cnv.line_width(1);
   cnv.stroke();
```

<1> Move the origin to the centre of `r`. The three calls read outward
    from the rectangle, so this one is applied last.
<2> Turn user space a twelfth of a turn about that origin.
<3> Move the centre of `r` to the origin, applied first.
<4> Outline `r` after the state ends. The transform is back, so the
    outline lands square to the axes.
