= Context

== Overview

A canvas is a view onto a drawing context that something else owns. It does
not create the context and does not free it, so it has to be destroyed
before whatever it borrowed the context from. It cannot be copied, moved or
assigned, so it is passed by reference; `draw(canvas& cnv)` is the shape
every host uses.

Usually you do not construct one. The host window creates a canvas for its
drawing area and hands it to you for the duration of the draw call, and it
is gone again when the call returns. To draw into an image instead,
construct one yourself on the context of an
xref:foundation/image.adoc[`offscreen_image`]. The examples throughout this
reference are drawn that way.

Underneath the canvas is the backend's own drawing context, and `impl()`
hands it back. That is the way out of Artist for the one facility the
library does not wrap, and the way in for a host that already has a context
of its own.

NOTE: See xref:canvas.adoc[Canvas] for the drawing model and an overview of the canvas.

== Include

```c++
#include <artist/canvas.hpp>
```

== Declaration

```c++
class canvas
{
public:

   explicit          canvas(canvas_impl* context);
                     ~canvas();

   canvas_impl*      impl() const;
   explicit          operator bool() const;
   bool              operator!() const;

   // Transforms, Current Path, Styles, Gradients, Rectangles, Text,
   // Drawing Images and States, each on its own page.
};
```

`canvas_impl` is the backend's drawing context type, named once per backend
in `canvas.hpp`. See <<Accessors>>.

== Expressions

The context members of xref:canvas.adoc[`canvas`] allow these expressions.

=== Notation

`cnv`    :: Object of type `canvas`.
`ctx`    :: Object of type `canvas_impl*`, a backend drawing context.

=== Constructor

[cols="1,1"]
|===
| Expression          | Semantics

| `canvas(ctx)`       | Construct a `canvas` drawing on `ctx`, which it
                        borrows and does not own.
|===

NOTE: C++ brace initialization may also be used.

The constructor is explicit, so a `canvas_impl*` does not convert to a
`canvas` on its own. `canvas` is non-copyable.

The canvas holds the pointer it was given and keeps drawing through it for
its whole life, so `ctx` has to outlive the canvas. Where the context comes
from decides how long that is:

* A host window makes one for each draw call and passes the canvas down by
  reference. The reference is good for the duration of that call only, and
  keeping it past the return leaves a canvas on a dead context.
* xref:foundation/image.adoc[`offscreen_image::context()`] draws into an
  image held in memory, whose pixels can be read back and saved. It is good
  while the `offscreen_image` lives, so the canvas goes out of scope first
  and the image is complete when it does.
* xref:foundation/canvas_layer.adoc[`canvas_layer::context()`] draws into a
  surface on the canvas's own device, the GPU where the canvas renders
  there, at the canvas's pixel density and with no pixel access. It is good
  while the layer lives, and only for the canvas the layer was made for.

Destroying the canvas does not destroy the context, and does not put the
context back the way it was found. Whatever the last drawing call left in
the backend's own state is still there. A host that reuses one context for
more than one canvas saves and restores around each of them, as the Skia
host does.

=== Accessors

[cols="1,1,1"]
|===
| Expression    | Semantics                               | Return Type

| `bool(cnv)`   | Get `true` if the canvas holds a
                  context.                                | `bool`
| `!cnv`        | Get `true` if the canvas holds no
                  context.                                | `bool`
| `cnv.impl()`  | Get the context the canvas was built
                  with, the same pointer that was passed
                  in.                                     | `canvas_impl*`
|===

The conversion to `bool` is explicit, so it converts in a condition and
nowhere else.

WARNING: There is no portable way to reach a canvas for which `bool(cnv)`
is `false`. Only a canvas built from a null `canvas_impl*` is invalid, and
the Cairo, Skia and Direct2D constructors dereference the pointer before
the object exists: on Cairo a null context is a measured segmentation
fault. Quartz 2D and the recording backend survive it and report `false`.
Test the context before building the canvas, not the canvas after.

`canvas_impl` is a different type on every backend, and only one of them is
declared in any one build. Which one follows from the backend the library
was compiled for:

[cols="1,1"]
|===
| Backend       | `canvas_impl`

| Cairo         | `cairo_t`
| Skia          | `SkCanvas`
| Quartz 2D     | Incomplete. The pointer is a `CGContextRef`, so it is
                  cast at both ends: the host hands the constructor a
                  `(canvas_impl*) cg_ctx`, and `CGContextRef(cnv.impl())`
                  gets it back.
| Direct2D      | `d2d::context`, Artist's own wrapper rather than a
                  Direct2D interface.
| Recording     | `recording::canvas_impl`, the journal the headless
                  backend appends to.
|===

Use `impl()` only for a facility of the backend that Artist does not
expose. Code that does builds only on that backend; the rest of this
reference is portable across all of them.

NOTE: The W3C canvas API has no counterpart. A browser context is the
drawing surface, where an Artist `canvas` is a view onto a surface the host
made, so Artist needs a way to name the surface and the W3C API does not.

=== Example

Write the function a host calls with the canvas for its drawing area, sized
to whatever that canvas turns out to be.

```c++
#include <artist/canvas.hpp>
...
using namespace cycfi::artist;

   void draw(canvas& cnv)                                   <1>
   {
      auto bounds = cnv.clip_extent();                      <2>
      auto dot = circle{center_point(bounds), 40};

      // Set the style, build the path, then paint it.
      cnv.fill_style(rgba(21, 101, 192, 255));
      cnv.add_round_rect(bounds.inset(20), 12);
      cnv.fill();

      cnv.fill_style(colors::white);
      cnv.add_circle(dot);
      cnv.fill();

      // The fill above consumed the circle, so it is added again here.
      cnv.stroke_style(rgba(26, 26, 26, 255));
      cnv.line_width(5);
      cnv.add_circle(dot);                                  <3>
      cnv.stroke();
   }
```

<1> Take the canvas by reference, as every host passes it.
<2> Size the panel to the clip region, so the function fits whatever
    canvas it is given. The figure below was drawn on a canvas over an
    xref:foundation/image.adoc[`offscreen_image`], and `clip_extent()`
    sized the panel to the image.
<3> Add the circle again for the ring.
    xref:canvas/current_path.adoc[`fill` consumes the path], so there is
    nothing left to stroke after the disc is filled.
