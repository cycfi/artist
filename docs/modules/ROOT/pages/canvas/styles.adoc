= Styles

== Overview

The styles decide how `fill` and `stroke` render: the paint each uses, the
width and shape of a stroke, the shadow cast under what is drawn, and how
new drawing combines with what is already on the canvas. Each is canvas
state. Set one and it stays in effect for every paint that follows, until
it is set again or a saved state is restored over it. Every style on this
page is part of the state that `save` and `restore` keep, so the usual way
to apply a style to one shape is inside a
xref:canvas/states.adoc[saved state].

A style is read when the path is painted, not when it is set, so set it
before `fill` or `stroke`. The geometry it paints is the
xref:canvas/current_path.adoc[current path].

NOTE: Artist follows the W3C canvas API, and the styles map onto its
`fillStyle`, `strokeStyle`, `lineWidth`, `lineCap`, `lineJoin`,
`miterLimit`, the four `shadow` attributes and `globalCompositeOperation`.
They behave as the W3C API specifies, the same on every backend.

== Include

```c++
#include <artist/canvas.hpp>
```

== Declaration

```c++
   enum line_cap_enum
   {
      butt,
      round,
      square
   };

   enum join_enum
   {
      bevel_join,
      round_join,
      miter_join
   };

   enum composite_op_enum
   {
      source_over,
      source_atop,
      source_in,
      source_out,

      destination_over,
      destination_atop,
      destination_in,
      destination_out,

      lighter,
      darker,
      copy,
      xor_,

      difference,
      exclusion,
      multiply,
      screen,

      color_dodge,
      color_burn,
      soft_light,
      hard_light,

      hue,
      saturation,
      color_op,
      luminosity
   };

   void     fill_style(color c);
   void     stroke_style(color c);
   void     fill_style(linear_gradient const& gr);
   void     fill_style(radial_gradient const& gr);
   void     stroke_style(linear_gradient const& gr);
   void     stroke_style(radial_gradient const& gr);
   void     fill_color(color c);
   void     stroke_color(color c);

   void     line_width(float w);
   void     line_cap(line_cap_enum cap);
   void     line_join(join_enum join);
   void     miter_limit(float limit = 10);

   void     shadow_style(point offset, float blur, color c);
   void     shadow_style(float offsetx, float offsety, float blur, color c);
   void     shadow_style(float blur, color c);

   void     global_composite_operation(composite_op_enum mode);
   void     composite_op(composite_op_enum mode);
```

All of these are members of `canvas`, and the enums are nested in it, so
the values are spelled `canvas::round`, `canvas::miter_join`,
`canvas::copy` and so on.

== Expressions

=== Notation

`cnv`                :: Object of type `canvas`.
`c`                  :: Object of type xref:foundation/color.adoc[color].
`gr`                 :: Object of type `canvas::linear_gradient` or
                        `canvas::radial_gradient`.
`w`                  :: A `float` line width.
`limit`              :: A `float` miter limit, a multiple of the line width.
`offset`             :: Object of type xref:foundation/point.adoc[point],
                        the displacement of a shadow.
`offsetx`, `offsety` :: `float` components of the displacement.
`blur`               :: A `float`, the softness of a shadow.
`mode`               :: A `canvas::composite_op_enum`.

=== Paint

[cols="1,1,1"]
|===
| Expression              | Semantics                          | Return Type

| `cnv.fill_style(c)`     | Fill with the flat color `c`.      | `void`
| `cnv.fill_style(gr)`    | Fill with the gradient `gr`.       | `void`
| `cnv.stroke_style(c)`   | Stroke with the flat color `c`.    | `void`
| `cnv.stroke_style(gr)`  | Stroke with the gradient `gr`.     | `void`
| `cnv.fill_color(c)`     | The same as `cnv.fill_style(c)`.   | `void`
| `cnv.stroke_color(c)`   | The same as `cnv.stroke_style(c)`. | `void`
|===

image::canvas/paint.png[alt="A color and a gradient, each as a fill and as a stroke", width=560px, align=center, title="A color and a gradient, each as a fill and as a stroke.", link={imagesdir}/canvas/paint.png]

Fill and stroke are separate styles, so one path can be filled in one paint
and outlined in another. Each holds one paint at a time: setting a color
replaces a gradient, and setting a gradient replaces a color. Both start as
opaque black.

The fill style also paints `fill_text` and `fill_rect`, and the stroke style
`stroke_text` and `stroke_rect`. How a gradient is built, and the space its
coordinates are in, is under xref:canvas/gradients.adoc[Gradients].

=== Line Width

[cols="1,1,1"]
|===
| Expression              | Semantics                          | Return Type

| `cnv.line_width(w)`     | Stroke `w` units wide, centred on
                            the path, half on each side.       | `void`
|===

image::canvas/line_width.png[alt="Three widths on the same path", width=560px, align=center, title="Three widths. The white line is the path.", link={imagesdir}/canvas/line_width.png]

The default width is 1. A width that is zero, negative, infinite or NaN is
ignored, and the width stays what it was.

The width is in user space, under the transform in effect when the path is
stroked, not when the width is set. After `cnv.scale(2)`, a width of 10
strokes 20 device units wide, whichever call came first.

=== Line Cap

[cols="1,1,1"]
|===
| Expression                       | Semantics                 | Return Type

| `cnv.line_cap(canvas::butt)`     | End a stroke exactly at
                                     the end of the path. The
                                     default.                  | `void`
| `cnv.line_cap(canvas::round)`    | Extend it past the end by
                                     a half circle whose radius
                                     is half the line width.   | `void`
| `cnv.line_cap(canvas::square)`   | Extend it past the end by
                                     half the line width,
                                     squared off.              | `void`
|===

image::canvas/line_cap.png[alt="A line under each cap", width=560px, align=center, title="The same line under each cap. The grey guides mark where the path ends.", link={imagesdir}/canvas/line_cap.png]

A cap is drawn at the two open ends of a sub-path. A sub-path closed with
`close_path` has no ends, and its corners are joins instead.

=== Line Join

[cols="1,1,1"]
|===
| Expression                          | Semantics              | Return Type

| `cnv.line_join(canvas::bevel_join)` | Cut the corner flat,
                                        across the outer edges
                                        of the two segments.   | `void`
| `cnv.line_join(canvas::round_join)` | Round the corner with
                                        an arc whose radius is
                                        half the line width.   | `void`
| `cnv.line_join(canvas::miter_join)` | Extend the outer edges
                                        of both segments until
                                        they meet in a point.
                                        The default.           | `void`
| `cnv.miter_limit(limit)`            | Cut a miter back to a
                                        bevel when it would be
                                        longer than `limit`
                                        line widths.           | `void`
| `cnv.miter_limit()`                 | Set the limit to 10,
                                        the default.           | `void`
|===

image::canvas/line_join.png[alt="A corner under each join", width=560px, align=center, title="The same corner under each join.", link={imagesdir}/canvas/line_join.png]

A miter grows as the angle between two segments closes. At an angle θ it is
1 / sin(θ / 2) line widths long, so a limit of 10 keeps a miter at any angle
above about 11.5 degrees and bevels anything sharper. A limit of 2 bevels
everything below 60 degrees. The limit only applies to `canvas::miter_join`.
A limit that is zero, negative, infinite or NaN is ignored.

image::canvas/miter_limit.png[alt="A sharp corner under two miter limits", width=560px, align=center, title="A 24 degree corner: its miter is 4.8 line widths long, inside a limit of 10 and cut back to a bevel by a limit of 2.", link={imagesdir}/canvas/miter_limit.png]

=== Shadow

[cols="1,1,1"]
|===
| Expression                      | Semantics                   | Return Type

| `cnv.shadow_style(offset,
    blur, c)`                      | Cast a shadow of color `c`
                                    under everything drawn
                                    afterwards, displaced by
                                    `offset` and softened by
                                    `blur`.                     | `void`
| `cnv.shadow_style(offsetx,
    offsety, blur, c)`             | As above, with the offset
                                    as two scalars.             | `void`
| `cnv.shadow_style(blur, c)`     | As above, with no offset,
                                    so the shadow spreads
                                    evenly around the shape: a
                                    glow.                       | `void`
|===

image::canvas/shadow.png[alt="Four shadows", width=560px, align=center, title="A hard shadow, a soft one, a glow, and the shadow of a half-transparent shape.", link={imagesdir}/canvas/shadow.png]

The shadow is what is drawn, in `c`, blurred, moved by `offset`, and put
down beneath it. Fills, strokes, text and images all cast one. Its strength
is the alpha of what is drawn, point by point, times the alpha of `c`: a
half-transparent shape casts a half-strength shadow, and the parts of a
gradient that fade out cast less.

`offset` and `blur` are in the canvas's own units and are not changed by
the transform: after `cnv.scale(2)` or a rotation, an offset of 10 across
is still 10 across. On an image with a scale, they are in the image's
units, not its pixels. `blur` is twice the standard deviation of the
Gaussian that softens the edge, so a shadow fades out over roughly `blur`
units on either side of it. A `blur` of zero gives a hard-edged copy.

A shadow is drawn only when it can be seen: when `c` is not fully
transparent, and `offset` or `blur` is not zero.

TIP: There is no call to turn a shadow off. Set it inside a saved state and
let the restore remove it:

```c++
   {
      auto s = cnv.new_state();
      cnv.shadow_style({0, 2}, 6, colors::black.opacity(0.4));
      cnv.fill_round_rect(panel, 8);
   }  // no shadow from here on
```

Setting a fully transparent shadow color, or no offset and no blur, turns it
off too.

=== Compositing

[cols="1,1,1"]
|===
| Expression                                | Semantics        | Return Type

| `cnv.composite_op(mode)`                  | Combine what is
                                              drawn afterwards
                                              with what is
                                              already on the
                                              canvas by
                                              `mode`.          | `void`
| `cnv.global_composite_operation(mode)`    | The same, under
                                              its W3C name.    | `void`
|===

In the table below the _source_ is what is being drawn and the
_destination_ is what is already on the canvas. The first twelve modes are
the Porter-Duff operators and their relatives, which decide how much of each
survives. The last twelve are blend modes, which mix the two colors where
they overlap and then draw the result over the destination.

[cols="1,2"]
|===
| Mode                         | Result

| `canvas::source_over`        | The source over the destination. The
                                 default.
| `canvas::source_atop`        | The source only where the destination
                                 is, over it. The rest of the destination
                                 is kept.
| `canvas::source_in`          | The source only where the destination
                                 is. The destination is not shown.
| `canvas::source_out`         | The source only where the destination
                                 is not. The destination is not shown.
| `canvas::destination_over`   | The source behind the destination.
| `canvas::destination_atop`   | The source behind the destination, and
                                 the destination only where the source is.
| `canvas::destination_in`     | The destination only where the source
                                 is. The source is not shown.
| `canvas::destination_out`    | The destination only where the source
                                 is not: the source erases.
| `canvas::lighter`            | The sum of the two colors.
| `canvas::darker`             | The smaller of the two colors, channel
                                 by channel.
| `canvas::copy`               | The source alone, alpha included,
                                 replacing the destination.
| `canvas::xor_`               | Each only where the other is not.
| `canvas::difference`         | The absolute difference of the two.
| `canvas::exclusion`          | Like `difference`, with less contrast.
| `canvas::multiply`           | The product of the two: always as dark as
                                 either.
| `canvas::screen`             | The inverse of the product of the
                                 inverses: always as light as either.
| `canvas::color_dodge`        | The destination brightened by the
                                 source.
| `canvas::color_burn`         | The destination darkened by the source.
| `canvas::soft_light`         | Darken or lighten by the source, gently.
| `canvas::hard_light`         | Multiply or screen by the source.
| `canvas::hue`                | The hue of the source, with the
                                 saturation and luminosity of the
                                 destination.
| `canvas::saturation`         | The saturation of the source, with the
                                 hue and luminosity of the destination.
| `canvas::color_op`           | The hue and saturation of the source,
                                 with the luminosity of the destination.
                                 The W3C `color` mode.
| `canvas::luminosity`         | The luminosity of the source, with the
                                 hue and saturation of the destination.
|===

image::canvas/composite_ops.png[alt="The first twelve modes", width=560px, align=center, title="The first twelve modes: a circle drawn over a square. The checkerboard shows where nothing is left.", link={imagesdir}/canvas/composite_ops.png]

image::canvas/blend_modes.png[alt="The twelve blend modes", width=560px, align=center, title="The twelve blend modes, with gradients so the mix varies across the overlap.", link={imagesdir}/canvas/blend_modes.png]

`source_in`, `source_out`, `destination_in`, `destination_atop` and `copy`
also clear the destination everywhere outside what is drawn, as far as the
clip, since the source is transparent there. Draw with them inside a clip
when the rest of the canvas matters.

NOTE: The enum has no W3C `clear`. `destination_out` with an opaque source,
or `clear_rect`, does the same job.

== Example

A panel, the `rect` `panel`, with a soft drop shadow and a rounded outline.
The shadow is scoped to the fill, so the outline casts none:

```c++
   {
      auto s = cnv.new_state();
      cnv.shadow_style({0, 2}, 6, colors::black.opacity(0.4));
      cnv.fill_style(colors::white);
      cnv.fill_round_rect(panel, 8);
   }

   cnv.stroke_style(colors::gray[40]);
   cnv.line_width(1);
   cnv.line_join(canvas::round_join);
   cnv.stroke_round_rect(panel, 8);
```
