= Resources

== Overview

Artist loads images by file name, and the name may be relative. A relative
name is resolved against a process wide list of search directories: the
first directory in the list that contains the file wins. The host
application seeds the list, and applications add to it with
`add_search_path`. `find_file` and `find_directory` search it.

Only the `image` constructors consult this list. Fonts are located
through `get_user_fonts_directory()` and the platform's own font
machinery; see xref:foundation/font.adoc[Font].

The list is guarded by a mutex, so `add_search_path` may be called from
any thread, including while another thread is searching.

NOTE: See xref:foundation.adoc[Foundation] for an overview of the foundation classes.

== Include

```c++
#include <artist/resources.hpp>
```

== Declaration

```c++
void      add_search_path(fs::path const& path, bool search_first = false);
fs::path  find_file(fs::path const& file);
fs::path  find_directory(fs::path const& dir);

// Supplied by the host application
extern void init_paths();
```

`fs` is the alias `cycfi::fs`, which `<infra/filesystem.hpp>` sets to
`std::filesystem`, or to `ghc::filesystem` on a toolchain without it. The
header includes it, and the alias is visible inside `cycfi::artist`.

== Client Interface

`init_paths` is declared by the library and defined by the host
application, to seed the search list. The library calls it the first time
`find_file` or `find_directory` runs; the application does not call it.
Every host under `examples/host/` provides one, typically adding the
application's resource directory.

`void init_paths();` ::
    Seed the search list through `add_search_path`. Example: the
    application bundle's resources directory on macOS, or `resources`
    under the current directory.

WARNING: A program that links Artist must define `init_paths()` or it
does not link. The companion hook, `get_user_fonts_directory()`, is
declared in `font.hpp` and is usually defined alongside it; see
xref:foundation/font.adoc#_client_interface[Font].

NOTE: `find_file` and `find_directory` each carry their own one time
initializer, so `init_paths()` runs once per function, up to twice in a
process that calls both. A directory it adds then appears in the list
twice. The comment in `resources.hpp` says it runs only once; do not rely
on either count.

== Expressions

=== Notation

`p`   :: Object of type `fs::path` for a directory to search.
`f`   :: Object of type `fs::path` for a file name, relative or absolute.
`d`   :: Object of type `fs::path` for a directory name, relative or
         absolute.

=== Functions

[cols="1,1,1"]
|===
| Expression                 | Semantics                       | Return Type

| `add_search_path(p)`       | Append `p` to the list, to be
                               searched after every directory
                               already present.                | `void`
| `add_search_path(p, true)` | Insert `p` at the front of the
                               list, to be searched first.     | `void`
| `find_file(f)`             | Get the path of `f`: `f` itself
                               when it is absolute and exists,
                               otherwise `p / f` for the first
                               `p` in the list where it exists,
                               and an empty path when nothing
                               matches.                        | `fs::path`
| `find_directory(d)`        | Get the path of `d` as
                               `find_file` does, where a match
                               must be a directory.            | `fs::path`
|===

`add_search_path` does not check that `p` exists and does not remove
duplicates. Adding the same directory twice searches it twice.

NOTE: `find_file` tests each candidate with `fs::exists`, which is true
for a directory as well as a file, so a relative name that happens to
match a directory is returned. `find_directory` is strict: it tests with
`fs::is_directory` and never returns a file. There is no function that
accepts only files.

An absolute path bypasses the list entirely. It is returned when it
exists and an empty path when it does not, whatever the list holds.

=== Example

Seed the search list in the host, then add the application's own
directories and resolve an image by name.

```c++
#include <artist/resources.hpp>
#include <artist/image.hpp>              // For image
...
namespace cycfi::artist
{
   void init_paths()                                         <1>
   {
      add_search_path(fs::current_path() / "resources");
   }
}
...
using namespace cycfi::artist;
extern cycfi::fs::path user_override_dir;   // set by the user, or empty
void use(cycfi::fs::path const& p);         // the application's own
...
   add_search_path("assets/textures");                       <2>
   if (!user_override_dir.empty())
      add_search_path(user_override_dir, true);              <3>

   image tex{"wood.png"};                                    <4>

   if (auto p = find_file("wood.png"); !p.empty())           <5>
      use(p);
```

<1> Define the hook in the host, seeding the list with `resources` under
    the current directory. See <<_client_interface>>.
<2> Add the application's own asset directory, searched after the host's.
<3> Add an optional override directory, searched before everything else.
<4> Construct an image from a relative name, resolved through the list.
<5> Resolve the name directly, and decide what to do on a miss.
