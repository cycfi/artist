= Rect

== Overview

A `rect` is an axis aligned rectangle held as four `float` edge
coordinates: `left`, `top`, `right` and `bottom`. It is not an origin and
a size. `width()` and `height()` are computed from the edges, and the
constructors that do take an xref:foundation/point.adoc[`extent`] convert
to edges on the way in.

Artist uses screen coordinates, so `y` increases *downward*: `top` is the
smaller `y` and `bottom` the larger. A rectangle whose edges are in that
order is *valid*, which `is_valid` tests. Nothing enforces it. `rect` is a
value type with no invariant, and several operations can hand back a rect
that fails `is_valid`; each is flagged below.

Everything declared in the header is `constexpr` except the seven
functions defined in `rect.cpp`: `intersects`, `union_`, `intersection`,
and the `center` and `align` families. A rect can be built, measured,
moved and inset at compile time, but not intersected or aligned there.

NOTE: `rect.hpp` includes `artist/point.hpp`, so `point`, `extent` and
`axis` come with it.

== Expressions

=== Notation

`r`, `r2`         :: Objects of type `rect`.
`encl`            :: An enclosing `rect`.
`p`, `p2`         :: Objects of type `point`.
`e`               :: Object of type `extent`.
`a`               :: Object of type `axis`.
`left`, `top`, `right`, `bottom` :: Floating point edge coordinates.
`x`, `y`          :: Floating point coordinates.
`w`, `h`          :: A floating point width and height.
`dx`, `dy`        :: Floating point distances.

=== Constructors and Assignment

[cols="1,1"]
|===
| Expression                        | Semantics

| `rect{}`                          | Default construct `{0, 0, 0, 0}`, an
                                      empty rect at the origin.
| `rect{left, top, right, bottom}`  | Construct from the four edges.
| `rect{origin, right, bottom}`     | Construct from a top left `point`
                                      and the *absolute* right and bottom
                                      edges.
| `rect{top_left, bottom_right}`    | Construct from the two opposite
                                      corners.
| `rect{left, top, e}`              | Construct from the top left edges
                                      and a size. The right edge is
                                      `left + e.x`, the bottom
                                      `top + e.y`.
| `rect{origin, e}`                 | Construct from a top left `point`
                                      and a size.
| `rect(r)`                         | Copy construct from `r`.
| `r = r2`                          | Assign `r2` to `r`.
|===

CAUTION: `rect{origin, right, bottom}` takes *absolute* edges, while
`rect{origin, e}` takes a size. The two have the same shape at the call
site and different meanings: `rect{point(10, 10), 100, 100}` is 90 by 90,
`rect{point(10, 10), extent(100, 100)}` is 100 by 100. Reach for the
`extent` form whenever the second argument is a size.

NOTE: `rect` has user declared constructors, so it is not an aggregate.
All four members are set by whichever constructor runs. As with
xref:foundation/point.adoc[`point`], brace initialization forbids
narrowing, so `rect(n, 0, w, h)` with an `int` `n` needs parentheses.

=== Comparison

[cols="1,1,1"]
|===
| Expression   | Semantics                                   | Return Type

| `r == r2`    | Compare all four edges. The comparison is
                 exact, so two rects differing only by
                 rounding are not equal.                     | `bool`
| `r != r2`    | The negation of the above.                  | `bool`
|===

=== Members

The members are public and directly assignable.

[cols="1,1,1"]
|===
| Expression  | Semantics                                    | Return Type

| `r.left`    | The left edge, the smaller `x`.              | `float`
| `r.top`     | The top edge, the smaller `y`.               | `float`
| `r.right`   | The right edge, the larger `x`.              | `float`
| `r.bottom`  | The bottom edge, the larger `y`.             | `float`
|===

=== Query

[cols="1,1,1"]
|===
| Expression        | Semantics                              | Return Type

| `r.is_empty()`    | `true` if *either* dimension is
                      degenerate, that is if
                      `left == right` or `top == bottom`.    | `bool`
| `r.includes(p)`   | `true` if `p` lies within `r`. The
                      test is inclusive on all four edges,
                      so a point on the border is included.  | `bool`
| `r.includes(r2)`  | `true` if all four edges of `r2` lie
                      within `r`. Inclusive, so `r`
                      includes itself.                       | `bool`
|===

IMPORTANT: `is_empty()` is not `r.size() == extent(0, 0)`. One degenerate
dimension is enough: `rect(0, 0, 100, 0)` is empty and its `size()` is
`{100, 0}`.

=== Accessors

[cols="1,1,1"]
|===
| Expression          | Semantics                            | Return Type

| `r.width()`         | `right - left`. Negative if `r` is
                        invalid.                             | `float`
| `r.height()`        | `bottom - top`. Negative if `r` is
                        invalid.                             | `float`
| `r.size()`          | `{width(), height()}` as an
                        `extent`.                            | `extent`
| `r.top_left()`      | `{left, top}`.                       | `point`
| `r.top_right()`     | `{right, top}`.                      | `point`
| `r.bottom_left()`   | `{left, bottom}`.                    | `point`
| `r.bottom_right()`  | `{right, bottom}`.                   | `point`
|===

=== Mutators

These modify `r` in place and return nothing, unlike the derivation
members below.

[cols="1,1,1"]
|===
| Expression     | Semantics                                 | Return Type

| `r.width(w)`   | Set the width by moving the *right* edge
                   to `left + w`. The left edge does not
                   move.                                     | `void`
| `r.height(h)`  | Set the height by moving the *bottom*
                   edge to `top + h`. The top edge does not
                   move.                                     | `void`
| `r.size(e)`    | Both of the above, from an `extent`.      | `void`
| `clear(r)`     | Set all four edges to zero, which leaves
                   an empty rect at the origin. A free
                   function, not a member.                   | `void`
|===

`clear` is worth knowing because `inset` calls it; see the caution under
<<Derivation>>.

=== Derivation

Each is `const` and returns a new rect; `r` is not modified.

[cols="1,1,1"]
|===
| Expression           | Semantics                           | Return Type

| `r.move(dx, dy)`     | A copy of `r` displaced by `dx` and
                         `dy`. All four edges shift, so the
                         size is unchanged.                  | `rect`
| `r.move_to(x, y)`    | A copy of `r` with its *top left
                         corner* at `{x, y}`, the size
                         unchanged.                          | `rect`
| `r.inset(x, y)`      | A copy of `r` shrunk by `x` on the
                         left and right and by `y` on the
                         top and bottom, so the width drops
                         by `2x` and the height by `2y`. A
                         negative argument grows the rect.   | `rect`
| `r.inset(xy)`        | The same distance on both axes.     | `rect`
|===

CAUTION: `inset` clamps, and it clamps hard. If the inset would leave an
invalid rect, the result is not a negative rect but `{0, 0, 0, 0}`: the
implementation calls `clear` on it, which discards the position as well as
the size. Over-insetting on one axis alone is enough, so
`rect(0, 0, 100, 60).inset(40)` is `{0, 0, 0, 0}` rather than a rect
20 wide. Check `width()` and `height()` against the inset first if the
distance is not known to be small. This is the opposite of
xref:foundation/circle.adoc[`circle::inset`], which does not clamp at all
and hands back a negative radius.

NOTE: `move_to` places the *top left corner*, where
xref:foundation/circle.adoc[`circle::move_to`] places the centre.

NOTE: There is no `inset()` with no arguments. The two overloads take one
or two distances and neither has a default argument.

== Free Functions

The notation of the previous section carries over.

=== Validity and Measurement

[cols="1,1,1"]
|===
| Expression            | Semantics                          | Return Type

| `is_valid(r)`         | `true` if `+left <= right+` and
                          `+top <= bottom+`. An empty rect
                          is valid; an inverted one is not.  | `bool`
| `is_same_size(r, r2)` | `true` if the widths match and the
                          heights match. Position is
                          ignored.                           | `bool`
| `center_point(r)`     | The midpoint,
                          `{left + width()/2,
                          top + height()/2}`.                | `point`
| `area(r)`             | `width() * height()`. Negative if
                          exactly one dimension is inverted. | `float`
| `intersects(r, r2)`   | `true` if the two rects overlap.
                          Not `constexpr`.                   | `bool`
|===

CAUTION: `intersects` is *strict* where `includes` is inclusive. Two rects
that share an edge do not intersect, yet each includes the points along
that edge. `rect(0, 0, 10, 10)` and `rect(10, 0, 20, 10)` give
`intersects` `false` and both give `includes(point(10, 5))` `true`.

=== Combination

Neither is `constexpr`.

[cols="1,1,1"]
|===
| Expression              | Semantics                        | Return Type

| `union_(r, r2)`         | The smallest rect covering both:
                            the min of the left and top
                            edges, the max of the right and
                            bottom.                          | `rect`
| `intersection(r, r2)`   | The overlap: the max of the left
                            and top edges, the min of the
                            right and bottom.                | `rect`
|===

IMPORTANT: `intersection` does not test for overlap first. On rects that
do not intersect it returns an inverted rect, for example
`{100, 100, 10, 10}`. Guard it with `intersects`, or test the result with
`is_valid`.

NOTE: `union_` takes no notice of emptiness, so `union_(rect{}, r)` always
stretches the result back to the origin. Skip the empty operand rather
than folding it in.

=== Placement

Each returns a copy of `r` repositioned inside `encl`; the size is never
changed and `encl` is never modified. None is `constexpr`.

[cols="1,1,1"]
|===
| Expression                  | Semantics                    | Return Type

| `center(r, encl)`           | `r` centred in `encl` on both
                                axes. The same result as
                                `align(r, encl, 0.5, 0.5)`.  | `rect`
| `center_h(r, encl)`         | Centred horizontally. `r.top`
                                is kept.                     | `rect`
| `center_v(r, encl)`         | Centred vertically. `r.left`
                                is kept.                     | `rect`
| `align(r, encl, x, y)`      | Positioned by two fractions.
                                `0` puts `r` against the
                                left or top of `encl`, `1`
                                against the right or bottom,
                                `0.5` centres it.            | `rect`
| `align_h(r, encl, x)`       | Horizontal fraction only.
                                `r.top` is kept.             | `rect`
| `align_v(r, encl, y)`       | Vertical fraction only.
                                `r.left` is kept.            | `rect`
|===

NOTE: The fractions are not clamped and nothing requires `r` to fit inside
`encl`. A fraction outside `0` to `1` places `r` outside `encl`, and if
`r` is the larger of the two the alignment runs the other way, which is
occasionally what you want.

=== Axis

These take an xref:foundation/point.adoc[`axis`] and pick the matching
edge or dimension, so a routine can be written once and run on either
direction. They are the `rect` counterpart of `point::operator[]`.

[cols="1,1,1"]
|===
| Expression                | Semantics                      | Return Type

| `axis_extent(r, a)`       | `width()` for `axis::x`,
                              `height()` for `axis::y`.      | `float`
| `axis_min(r, a)`          | `left` for `axis::x`, `top` for
                              `axis::y`. On a non-const
                              `rect` this is a reference, so
                              it assigns.                    | `float&`
| `axis_max(r, a)`          | `right` for `axis::x`, `bottom`
                              for `axis::y`. Also has a
                              reference form.                | `float&`
| `make_rect(a, this_min,
   other_min, this_max,
   other_max)`              | Build a rect from
                              along-the-axis and
                              across-the-axis edges. For
                              `axis::x` the arguments are
                              already `left, top, right,
                              bottom`; for `axis::y` the
                              pairs are swapped.             | `rect`
|===

NOTE: The four `axis` helpers are defined in `rect.hpp` but do not appear
in its Free Functions declaration block, so they are easy to miss when
skimming the header.

== Example

Laying a fixed size badge into the top right of a bounds rect, with a
margin, and taking the part of it that is actually on screen:

```c++
   auto slot = rect{0, 0, extent{64, 24}};
   auto badge = align(slot, bounds.inset(8), 1.0f, 0.0f);

   if (intersects(badge, clip))
   {
      auto visible = intersection(badge, clip);
      cnv.rect(visible);
      cnv.fill_style(colors::gray[90]);
      cnv.fill();
   }
```

And the same layout step written once for either axis:

```c++
   // Split r into two rects at a fraction along axis a.
   constexpr auto split(rect r, axis a, float frac)
   {
      auto at = axis_min(r, a) + (axis_extent(r, a) * frac);
      auto first = r, second = r;
      axis_max(first, a) = at;
      axis_min(second, a) = at;
      return std::make_pair(first, second);
   }
```
